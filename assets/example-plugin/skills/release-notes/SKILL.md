# Release Notes

Inspect the release diff and repository conventions before drafting. Use [the checklist](references/checklist.md), separate user-visible changes from internal work, and never invent a fix, compatibility claim, or test result.

Return a concise summary, grouped changes, breaking or migration actions, and exact validation evidence supplied by the repository.
